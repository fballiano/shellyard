# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Termora is a native macOS SSH connection manager (SwiftUI, Swift 6, strict
concurrency `complete`, macOS 26+). It embeds the Ghostty terminal engine
through libghostty. README.md is the user guide. Docs/DEVELOPMENT.md is
detailed and current; read it for the document format, the SSH
control-master design, the import pipeline, and the release process.

## Commands

`Termora.xcodeproj` is **generated by XcodeGen**. Never edit it. Change
`project.yml`, then run `xcodegen generate`.

```sh
# Build and launch the app (regenerates the project first)
./run.sh                # ./run.sh --install also copies to /Applications

# Build only
xcodegen generate
xcodebuild -project Termora.xcodeproj -scheme Termora \
           -configuration Debug -derivedDataPath build build

# Package tests (each package is an independent SwiftPM package)
(cd Packages/TermoraModel && swift test)
(cd Packages/TermoraVault && swift test)
(cd Packages/TermoraSSH && swift test)
(cd Packages/TermoraSFTP && swift test)
(cd Packages/TermoraImport && swift test)

# One test or one suite
(cd Packages/TermoraSSH && swift test --filter SSHIntegrationTests)

# UI tests (drive the real app)
xcodebuild -project Termora.xcodeproj -scheme Termora \
           -destination 'platform=macOS,arch=arm64' -derivedDataPath build test
```

Notes on tests:
- The SSH tests start their own OpenSSH server on a high port and never touch
  `~/.ssh`. They are skipped when `/usr/sbin/sshd` is missing.
- The SFTP tests talk to `/usr/libexec/sftp-server` directly: real protocol,
  no network, no keys.
- The UI tests write a vault document, then launch the app with
  `-TermoraLastDocumentPath <path>` (`UserDefaults` reads `-key value` from
  the command line). The app has no test-only code.
- Opt-in suites: `TERMORA_ROYAL_DOCUMENT=<path>` enables the real-document
  import tests; `TERMORA_TEST_ROYAL_BRIDGE=1 swift test --filter
  RoyalBridgeLiveTests` (in Packages/TermoraImport) starts the real Royal TSX
  app.

## Architecture

The app target (`Termora/`) is a thin SwiftUI shell over six local SwiftPM
packages in `Packages/`:

- **TermoraModel** — the bookmark/node tree and folder inheritance
  (`Inherited`, `NodeSettings`). Pure model, fully testable.
- **TermoraVault** — the encrypted `.termora` document (AES-256-GCM,
  PBKDF2-HMAC-SHA512, header as AAD) and the Touch ID key cache
  (`VaultKeyStore`).
- **TermoraSSH** — Termora never speaks the SSH protocol. It drives
  `/usr/bin/ssh` with one control master per connection; panes, the SFTP
  channel, and tunnels all attach to that socket (`-S <socket>`). Passwords
  reach OpenSSH through `SSH_ASKPASS` → the `termora-askpass` helper → a Unix
  socket back to the app. `AskpassClient.swift` is compiled into **both** the
  helper tool and the library (see `project.yml`), so keep the protocol in
  that one file.
- **TermoraImport** — the Royal TSX reader plus `RoyalTSXBridge`, an
  AppleScript bridge that asks Royal TSX for decrypted passwords. The bridge
  is `@MainActor` on purpose: `NSAppleScript` off the main thread hangs
  forever rather than failing.
- **TermoraSFTP** — an SFTP v3 client that runs over the control master's
  `-s sftp` channel. No cryptography of its own.
- **GhosttyKit** — the upstream `Lakr233/libghostty-spm` package, pinned
  with `exactVersion` in `project.yml`. It is the only remote dependency
  (it brings `Lakr233/DisplayLink` with it). **Always pin the newest
  upstream release**, majors included: list them with
  `git ls-remote --tags https://github.com/Lakr233/libghostty-spm`. Each
  release names the Ghostty commit it builds. Termora once carried a
  vendored fork with three fixes; all three are upstream since 1.4.5, so
  the copy is gone. Before pinning a newer version, check that the wakeup
  observers (`addWakeupObserver`), `TerminalViewState.isSurfaceVisible`,
  and `TerminalViewState.sendKey(_:)` are still there — each guards against
  a bug Termora hit.

In the app target, `Termora/Terminal/` is the only code that calls
libghostty. `Termora/Sessions/SessionsController.swift` owns tabs/splits
(a `TerminalTab` with no `connectionID` is a local shell tab);
`Termora/UI/` is the SwiftUI layer.

## Traps that have already cost time

- **Never remove a terminal tab from the view tree.** Tabs render in a
  `ZStack` with `opacity(0)` for hidden ones. `if let selectedTab` destroys
  the hidden `TerminalSurfaceView`, and libghostty cannot re-attach a surface
  — the tab goes permanently blank. Use
  `SessionsController.updateVisibility()` / `isSurfaceVisible` to stop
  drawing instead.
- **Do not use `.searchable` in the sidebar.** With `placement: .sidebar`
  the system draws its field above all other sidebar content, so nothing can
  sit above the filter. `SidebarView` has its own `FilterField` for this.
- **A new menu shortcut must also go in `GhosttyEnvironment.menuKeyTriggers`.**
  A focused pane takes every key that Ghostty binds (⌘T is `new_tab`), and the
  menu never sees it.
- **Do not pass an empty `TerminalTheme()`** — the package then paints its own
  colors over the user's Ghostty config. See `GhosttyEnvironment`.
- **A UI test target must not link a package the app also links** beyond what
  it imports itself. Linking `TermoraSSH` into `TermoraUITests` once stopped
  the app under test from opening any window, with no error.
- **OpenSSH output ends lines with CRLF, and Swift counts `\r\n` as one
  `Character`.** `split(separator: "\n")` returns the whole log as one line.
  Use `split(whereSeparator: \.isNewline)`.
- **`SwiftUI.Document` exists since the Xcode 27 SDK.** In a file that
  imports SwiftUI, a bare `Document` is ambiguous. Write
  `TermoraModel.Document`.
- **Swift 6.3.3 compiler crash:** passing a method reference straight to a
  `Binding` setter (`set: change`) crashes codegen. Write the closure out:
  `set: { newValue in change(to: newValue) }`.
- **No Keychain for Touch ID.** With an ad-hoc signature the
  `keychain-access-groups` entitlement fails (`-34018`) or kills the process
  at launch. `VaultKeyStore` uses the Secure Enclave + ECDH instead; keep it
  that way.
- **Secrets never go on a command line, in the environment, or in a file.**
  The askpass socket is the only route. An imported task containing
  `$PASSWORD$` is refused, and `LocalCommandRunner` never invokes a shell.
